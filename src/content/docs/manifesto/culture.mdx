## 核心文化

### 开源精神

我们要求主流项目默认公开源代码，并：

- 在公开仓库接收 issue 与 Pull Request
- 发布变更日志供社区审计
- 重大决策在讨论期公示

### 协作精神

协作以公开讨论为主：影响范围较大的变更须在公开渠道提出，并以 Pull Request 形式评审，避免一对一私下敲定。鼓励成员在 GitHub 上互相审阅与反馈。

### 创新精神

鼓励在具体问题上尝试更优方案；新工具或技术选型须附带可复现的评估依据，并经相关成员评审后再纳入主分支 [待补充：技术选型评审的具体流程与责任方]。

## 精神内核

### 用户至上

用户至上的完整表述见《使命与愿景》的价值观一节。在日常工作中，我们优先处理真实用户反馈，并将可用性作为功能验收标准之一。

## 行为准则

成员须遵守《内部成员行为守则》。在此补充两条可执行约束：

- 公开承诺的功能须有里程碑跟踪，未能交付时须主动说明。
- 评审与讨论不得进行人身攻击，意见须针对代码与方案本身。
