## 概述

ReCloud Studio 内部项目的代码采用 AGPL-3.0 协议许可，但访问权限仅限内部成员，因此不属于公开「开源」范畴。

> 说明：AGPL-3.0 本身是开源许可证，但「开源」还要求代码公开可获取。内部项目仅授权内部成员访问，对外不构成开源软件；其公开项目（见 [对外公开源代码](./public-license)）才是真正的开源项目。

## 内部项目特点

### 代码访问

- **访问范围**: 仅限 ReCloud Studio 内部成员
- **代码托管**: 使用内部 Git 仓库
- **权限管理**: 基于角色的访问控制

### 代码管理

- **代码审查**: 所有代码变更必须经过审查
- **分支管理**: 遵循统一的分支管理策略
- **版本发布**: 遵循语义化版本控制

## 内部成员权利

### 使用权

- **开发使用**: 可以用于内部项目开发
- **测试使用**: 可以用于内部测试
- **学习使用**: 可以用于内部学习和培训

### 修改权

- **功能修改**: 可以修改现有功能
- **Bug 修复**: 可以修复发现的 Bug
- **性能优化**: 可以优化代码性能

## 内部成员义务

### 代码质量

- **遵循规范**: 遵循项目的代码规范
- **编写测试**: 为新功能编写测试用例
- **文档更新**: 及时更新相关文档

### 安全要求

- **不得外泄**: 不得将代码泄露给外部人员
- **安全存储**: 必须安全存储代码和凭证
- **及时报告**: 发现安全问题必须立即报告
